    ESP32-S3 · ES3C28P · ILI9341 320 × 240

    Dessiner et animer l'écran 2,8" avec le moteur gfx

    Toutes les animations de la console « Lumière » sont calculées pixel par pixel par gfx.cpp, un moteur de dessin de 450 lignes écrit par Claude, l'IA d'Anthropic, sans LVGL. Cette page explique chaque fonction, montre chaque exemple en direct et déroule le montage pas à pas.

    L'écran ci-contre exécute la vitrine demo_gfx avec le moteur porté en JavaScript : même algorithme, même format de couleur, rendu identique au pixel près au simulateur C++. La souris ou le doigt jouent le rôle du tactile.

    • 153 600octets par image
    • 16bits par pixel (RGB565)
    • 2tampons, 2 cœurs
    • 0bibliothèque graphique externe
    Survolez l'écran : coordonnées et couleur320 × 240

    1 · Principe

    Une image en mémoire, envoyée d'un bloc

    Le programme ne dessine jamais directement sur l'écran. Il calcule une image complète dans un tableau d'entiers 16 bits placé en PSRAM (le tampon, gfx::fb), puis l'envoie en une seule fois par SPI avec tft.pushImage(). Cela évite le scintillement, permet la transparence (il faut pouvoir relire le pixel du dessous) et les bords lissés.

    ft6336_touch_read()"] --> U["Interface

    Le format de couleur RGB565

    Chaque pixel tient sur 16 bits : 5 pour le rouge, 6 pour le vert, 5 pour le bleu. gfx::rgb(r, g, b) fabrique cette valeur à partir de trois octets 0–255, à la compilation. Essayez :

    Demandée (24 bits)
    Affichée (16 bits)

    2 · Tutoriel pas à pas
    
      
    De l'écran noir à l'interface animée
    
      
    Douze étapes, dans l'ordre où on les réalise sur la carte. Chaque étape ajoute une brique au croquis ; les aperçus exécutent le code montré. Cochez les étapes au fur et à mesure (mémorisé dans ce navigateur).

    1
    
        
    Préparer l'IDE Arduino
    
        
      
          
    • Gestionnaire de cartes : paquet esp32 d'Espressif, version 3.x.
      • 
          
    • Carte ESP32S3 Dev Module, PSRAM OPI PSRAM, Flash 16 Mo, partition « 16M Flash (3MB APP/9.9MB FATFS) ».

    Sans PSRAM activée, l'allocation des tampons échoue : le programme se replie sur un seul tampon en mémoire interne, et les animations ralentissent.
    
        
      
    

      
    2
    
        
    Configurer TFT_eSPI pour l'ILI9341
    
        
    TFT_eSPI se règle dans son fichier User_Setup.h (dossier de la bibliothèque). Reprenez celui de la console NES, qui fonctionne déjà sur l'ES3C28P. Les lignes qui comptent :
    
        
    #define ILI9341_DRIVER
#define TFT_WIDTH  240
#define TFT_HEIGHT 320
// TFT_MOSI, TFT_SCLK, TFT_CS, TFT_DC, TFT_RST : broches de la carte ES3C28P
// (reprendre exactement celles du User_Setup.h de la console NES)
#define USE_HSPI_PORT
#define SPI_FREQUENCY  40000000   // 40 MHz ou plus : la fluidité en dépend
    
        
    La fréquence SPI fixe le temps d'envoi d'une image : 153 600 octets à 40 MHz prennent environ 31 ms, donc environ 30 images/s au maximum. L'étape 9 le montre.

    4
    
        
    Allumer l'écran
    
        
    Le rétroéclairage est sur la broche 45, piloté en PWM pour régler la luminosité. Puis on initialise l'écran en paysage.
    
        
    #include <Arduino.h>
#include <TFT_eSPI.h>
#include "esp_heap_caps.h"
#include "gfx.h"

#define LCD_BL_PIN 45
TFT_eSPI tft = TFT_eSPI();

void setup() {
    Serial.begin(115200);
    ledcAttachChannel(LCD_BL_PIN, 2000, 8, 0);   // PWM 2 kHz, 8 bits
    ledcWrite(LCD_BL_PIN, 204);                  // 80 % de luminosité
    tft.init();
    tft.setRotation(1);                          // paysage : 320 x 240
    tft.setSwapBytes(true);                      // ordre des octets RGB565
    tft.fillScreen(TFT_BLACK);
}
    
        
    Pourquoi setSwapBytes(true) ? L'ESP32 range l'octet de poids faible en premier, l'ILI9341 attend l'inverse. Avec cette option, pushImage retourne chaque pixel à l'envoi, et tout le reste du programme manipule des couleurs normales. Sans elle, le cyan devient un jaune sale.
    
        
      
    

      
    5
    
        
    Réserver le tampon d'image en PSRAM
    
        
    320 × 240 pixels × 2 octets = 153 600 octets. La mémoire interne de l'ESP32-S3 n'en garderait presque plus pour le reste ; la PSRAM de 8 Mo, si.
    
        
    static uint16_t *tampon = nullptr;

// dans setup(), après tft.init() :
tampon = (uint16_t *)heap_caps_malloc(320 * 240 * sizeof(uint16_t), MALLOC_CAP_SPIRAM);
if (!tampon) {
    tft.drawString("Memoire insuffisante", 10, 10, 2);
    for (;;) delay(1000);
}
gfx::init(tampon);     // gfx dessine désormais dans ce tableau
    
        
    Le pixel (x, y) est gfx::fb[y * 320 + x]. L'origine est en haut à gauche, y descend.
    
        
      
    

      
    6
    
        
    Premier dessin, premier envoi
    
        
    On dessine du fond vers l'avant : l'ordre des appels est l'ordre de superposition. Rien n'apparaît tant que pushImage n'est pas appelé.
    
        
    
          
    
          
    
        
    
        
      
    

      
    7
    
        
    Animer : redessiner à chaque image avec dt
    
        
    loop() redessine toute l'image en fonction du temps. On calcule dt, le temps écoulé depuis l'image précédente, et on exprime toutes les vitesses en unités par seconde. Changez le nombre d'images/s simulées : le point garde la même vitesse, seule la fluidité change.
    
        
    
          
    
          
    
            
    
            
    
          
    
        
    
        
      
    

      
    8
    
        
    Pré-calculer le fond
    
        
    Le dégradé et les grands halos du fond coûtent cher, et ils ne bougent pas. On les dessine une seule fois dans un deuxième tampon, puis on le recopie à chaque image avec gfx::copier() (un simple memcpy de 150 Ko).
    
        
    static uint16_t *fond = nullptr;

void preparer_fond() {
    fond = (uint16_t *)heap_caps_malloc(320 * 240 * 2, MALLOC_CAP_SPIRAM);
    uint16_t *ancien = gfx::fb;
    gfx::fb = fond;                                    // dessiner AILLEURS
    gfx::degrade_v(0, 0, 320, 240, gfx::rgb(4, 6, 18), gfx::rgb(16, 12, 42));
    gfx::halo(255, 50, 150, gfx::rgb(140, 92, 255), 34);
    gfx::halo(40, 210, 140, gfx::rgb(70, 120, 255), 26);
    gfx::fb = ancien;                                  // et revenir
}

// à chaque image :
gfx::copier(fond);
    
        
      
    

      
    9
    
        
    Double tampon sur les deux cœurs
    
        
    Avec un seul tampon, il faut attendre la fin de l'envoi avant de redessiner. Avec deux, le cœur 0 envoie l'image n pendant que le cœur 1 dessine l'image n+1. Réglez les temps et comparez.

    10
    
        
    Brancher le tactile
    
        
    Le FT6336 est en I²C (SDA 16, SCL 15, reset 18). On crée un seul bus avec le nouveau pilote ESP-IDF : le codec audio ES8311 pourra s'y attacher aussi. L'étalonnage 3 points est demandé seulement s'il n'existe pas en mémoire non volatile.
    
        
    #include "driver/i2c_master.h"
#include "ft6336_touch.h"

bool init_tactile() {
    i2c_master_bus_handle_t bus = NULL;
    i2c_master_bus_config_t cfg = {};
    cfg.i2c_port = I2C_NUM_0;
    cfg.sda_io_num = (gpio_num_t)16;
    cfg.scl_io_num = (gpio_num_t)15;
    cfg.clk_source = I2C_CLK_SRC_DEFAULT;
    cfg.glitch_ignore_cnt = 7;
    cfg.flags.enable_internal_pullup = true;
    if (i2c_new_master_bus(&cfg, &bus) != ESP_OK) return false;
    return ft6336_touch_init(bus, (gpio_num_t)18, 320, 240);
}

// dans setup() :
if (init_tactile() && !ft6336_touch_load_calibration()) etalonner();

// dans loop(), à chaque image :
int x = 0, y = 0;
bool appui = ft6336_touch_read(&x, &y);    // coordonnées écran 320 x 240
scene::toucher(appui, x, y);
    
        
      
    

      
    11
    
        
    Transformer les appuis en gestes
    
        
    Le pilote dit seulement « doigt posé en (x, y) » ou non. En comparant avec l'image précédente, on détecte le moment où le doigt se pose, glisse ou se lève. Essayez sur l'écran : un appui court donne un tap, un déplacement un glisser, un grand mouvement horizontal un balayage.
    
        
    
          
    
            
    stateDiagram-v2
    [*] --> Leve
    Leve --> Pose: doigt posé
    Pose --> Pose: glisse (bouge si plus de 6 px)
    Pose --> Leve: levé (tap, balayage ou fin de glisser)

    12
    
        
    Organiser l'interface et tester sur PC
    
        
    Le croquis ne garde que le matériel. Tout le dessin vit dans scene.cpp, qui n'inclut jamais Arduino.h : il compile aussi sur PC. Trois fonctions suffisent.
    
        
    namespace scene {
void init(uint16_t *fond);                 // une fois, au démarrage
void toucher(bool appui, int x, int y);    // à chaque image
void image(uint32_t ms);                   // dessine une image complète dans gfx::fb
}

    3 · Référence
    
      
    Toutes les fonctions de gfx
    
      
    Chaque fiche donne la signature, les paramètres, un aperçu réglable et le code C++ correspondant, prêt à copier. Conventions : coordonnées en pixels depuis le coin haut gauche, a = opacité 0–255 (255 par défaut), angles en radians, sens horaire puisque y descend. Les formes « lissées » acceptent des coordonnées décimales.

    4 · Animer
    
      
    Le laboratoire du mouvement
    
      
    Toutes les animations reposent sur quelques fonctions de quelques lignes. Une animation « à durée » applique une courbe à un âge (t − t0) / durée ; une animation « qui suit » rapproche à chaque image une valeur affichée de sa valeur cible.
    

      
    Courbes d'accélération
    
      
    
        
    
          
          
    
        
    
        
    
      
    

      
    approche() et ressort : suivre une cible
    
      
    La cible saute de 0 à 1 toutes les deux secondes. approche() la rejoint sans la dépasser ; le ressort la dépasse puis revient. Réglez les constantes et copiez le code.

    Performances, dépannage, LVGL
    

      
    Gagner des images par seconde
    
      
    ConseilPourquoi
    
        
    SPI_FREQUENCY ≥ 40 MHzL'envoi de 150 Ko est le premier facteur limitant.
    
        
    Fond pré-calculé + copier()Un memcpy coûte bien moins qu'un dégradé et des grands halos.
    
        
    Double tampon PSRAMDessin et envoi en parallèle sur les deux cœurs.
    
        
    rect plutôt que rect_arrondi pour les grandes surfacesrect n'a aucun calcul par pixel.
    
        
    Halos petitsLe coût croît comme le carré du rayon.
    
        
    Opaque si possibleUn pixel opaque est une écriture ; transparent = lecture + mélange.
    
        
    decoupe()Les pixels hors zone sont sautés avant tout calcul.
    
        
    MesurerLa vitrine affiche les images/s en haut à droite.
